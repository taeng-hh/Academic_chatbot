## Windows VS Code · Git Bash 실행

```bash
cd "프로젝트를_압축해제한_폴더/ExamAgent_Streamlit"
py -3.12 -m venv .venv
source .venv/Scripts/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
# 테스트까지 하려면: python -m pip install -r requirements-dev.txt
cp .env.example .env
# .env를 열어 OPENAI_API_KEY를 실제 키로 수정하세요.

```

## Streamlit Community Cloud 배포

1. 프로젝트를 **비밀값 없이** GitHub 저장소에 push합니다.
2. https://share.streamlit.io 에서 저장소와 `app.py`를 선택합니다.
3. 앱 설정 **Secrets**에 `OPENAI_API_KEY = "..."`를 저장합니다. (선택: `OPENAI_MODEL = "gpt-5.4-mini"`)
4. 앱을 재시작하고 실제 PDF·Excel을 업로드하여 확인합니다.
5. GitHub 저장소 → Settings → Collaborators → Add people → `jaypakdevkr`를 초대합니다.
6. 배포 URL·학번·이름을 README에 기입하고 제출합니다.

## 기술 선택

- **LangGraph + OpenAI Python SDK**를 사용합니다. 이 구조에서는 LangChain을 추가하지 않아도 라우팅 및 OpenAI Responses API 호출을 구현할 수 있으므로 설치 의존성을 줄였습니다.
- OpenAI 기본 모델은 `gpt-5.4-mini`입니다. 사용 가능 모델 및 비용에 따라 `.env`의 `OPENAI_MODEL`을 수정할 수 있습니다.
- 시각 문항은 문항·공통 지문의 좌표 영역을 렌더링해 필요한 때만 전달합니다. 스캔 PDF 자체의 OCR은 제공하지 않습니다.

## 설계 원칙

- 정답과 배점은 **매번 업로드 PDF에서 추출**하며 코드나 사전 생성된 파일에 저장하지 않음.
- Python이 채점·통계·공동순위를 계산하고 답변의 숫자를 직접 구성함. 명백한 질문은 API 없이 처리합니다. 애매한 질문만 OpenAI Structured Outputs로 복수 의도·학생/문항 참조·요청 통계·조건을 분류하고, 별도로 스키마를 검증합니다. LLM에 점수 계산이나 자유 형식의 성적 보고를 맡기지 않습니다.
- 의도 해석에는 현재 질문·최근 사용자 요청·직전 참조만 보내며 전체 학생 목록·OMR·정답표는 보내지 않습니다. 해설과 생성에는 선택한 문항 원문·필요한 영역 이미지만 전달합니다(`store=False`). 임의 Python·셸·파일시스템 실행 도구는 없습니다.
- 데이터는 Streamlit 세션 안에서만 관리. 페이지 새로고침 시 초기화될 수 있음.
- 파일 교체뿐 아니라 세 파일 중 하나를 삭제해도 이전 보고서·Excel·채팅·참조 대상·생성 캐시를 함께 초기화합니다.
- 문항 추출은 문항 번호 외에 선택지 수·공통 지문·원문 영역·시각 자료·완전성 상태를 기록합니다. 불완전 문항은 경고하고 문제 생성을 제한합니다. 좌표·완전성 판정은 휴리스틱이므로 모든 편집 형식을 보장하지 않습니다.
- 모집단 표준편차/분산을 사용합니다. 오답 동률은 오답 수 내림차순→문항 번호 오름차순, 학생 석차는 공동순위(1,1,3)입니다. 최고·최저 동점자는 모두 표시하고, 단일 대명사의 대상이 여러 명이면 재질문합니다.
- 유사 문제 사전 생성은 기본 OFF인 선택 기능입니다. 실패해도 채점·Excel은 계속 동작합니다. 생성 결과의 보기 5개·중복·빈값·정답 범위·해설 정답 필드와 명시적 결론의 일치를 검사합니다. 이는 해설의 논리적 정답성까지 보증하지는 않습니다.
- 그림·도표·듣기 자료의 원본 의미를 텍스트만으로 완전히 복원할 수 없음. 해당 유형은 추가 이미지·듣기 자료 지원이 필요함.
- 20초 응답 제한은 실제 배포 URL에서 측정. OpenAI API 사용량에 따라 요금 발생.

## 채팅 질문 범위

인사·감사 표현은 간단히 응답하고, 일상적인 질문은 일반 대화로 처리합니다. 요청하지 않은 시험 통계나 분석 메뉴를 자동으로 붙이지 않습니다. 복합 질문에 성적·문항 조회가 포함되면 자료 조회 경로를 사용하며, 평가 예시의 기본 조회·출석 정보 부재 응답·내부 정보 공개 거절·유사 문제 생성 경로를 유지합니다.

분석은 파일을 바꿀 때만 다시 실행하면 됩니다. 동일 세션에서는 계속 질문할 수 있습니다.

- 기본 조회: 평균·중앙값·표준편차·분산, 최고/최저 점수 학생(동점 포함), 학생 점수, 오답 순위, 문항 원문·정답.
- 순위 조회: 특정 등수·등수 범위·상위/하위 인원·공동석차·서로 다른 점수 순서. 일반적인 “2등”은 공동석차, “두 번째로 높은 점수”는 서로 다른 점수 순서로 처리합니다. 해당 석차가 없으면 없다고 답하며 동점자를 임의로 고르지 않습니다.
- 조건부 집계: 선택한 학생·상위 인원·석차 범위·점수 구간·평균/중앙값 기준 집단의 통계. 질문에 집단 조건이 있으면 전체 통계로 대신하지 않습니다.
- 확장 조회: 학생 순위와 비교, 점수 구간별 인원과 통계, 개인별 오답·미응답, 문항별 선택지 응답 분포와 응답 학생. 질문이 명백하면 직접 처리하고, 낯선 표현·복합 조건은 의도 해석에만 API를 사용합니다.
- 원문 기반 학습 지원: 문항 해석·어휘·문법·정답 해설, 주제 키워드 검색, 오답에 근거한 학습 조언, 지정 문항 또는 학생의 오답을 기준으로 유사 문제 생성.
- Excel은 기존 요약·학생별 O/X·문항별 분석을 유지하고, 학생별 석차·서로 다른 점수 순서·제출 답안·미응답·감점 시트를 추가합니다.
- 문제 생성은 기준 문항별 한 번에 1~5개를 요청할 수 있습니다. 여러 문제는 응답 시간 예산 안에서 순차 생성하며, 중간에 실패하면 이미 생성한 문제와 실패 안내를 함께 표시합니다. 난이도 요청과 추가 생성 요청에는 사전 생성 문제를 재사용하지 않습니다.
- 예: `80점 이상 학생은 몇 명이야?`, `87번 학생과 99번 학생의 오답을 비교해줘`, `21번에서 3번을 고른 학생은?`, `그 학생의 취약 문항을 설명해줘`, `33번 지문을 해석하고 정답 근거를 알려줘`.

추출된 문제 내용과 답안만 근거로 답합니다. 출석·과거 시험·제공되지 않은 듣기 대본은 확인할 수 없으며, 스캔 PDF는 먼저 OCR 변환이 필요합니다. 원문 추출 누락을 표시합니다. 한 대화 턴의 API 시간 예산은 약 18초, 의도 해석은 최대 5초이며 재시도는 하지 않습니다. 실제 네트워크·브라우저·클라우드 E2E 20초 달성은 별도로 실측해야 합니다. 화면에는 응답 처리 시간을 표시하지만 브라우저 페인트 완료까지의 측정값은 아닙니다.

구조화 출력 연결은 [OpenAI 공식 문서](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses)를 참고했습니다. 최근 구현 범위와 실행 여부는 [변경 기록](docs/IMPROVEMENT_REVIEW.md)에 기록합니다.
